关于密码学中 AES-256-GCM 的算法理解

2026-07-28 阅读约 5 分钟 阅读 -- 次

AES-256-GCM：Signal Protocol 中的认证加密基石

在 Signal Protocol 的完整加密体系中，AES-256-GCM 承担着最核心的职责——直接加密和解密每一条消息的内容。作为整个协议栈的“最后一公里”加密层，它的安全性直接决定了通信内容的机密性与完整性。

一、GCM 模式：为何选择它

AES-GCM（Galois/Counter Mode）是一种 AEAD（Authenticated Encryption with Associated Data，带关联数据的认证加密）算法。它在 CTR（Counter）模式加密的基础上增加了 GMAC（Galois Message Authentication Code）认证机制。这一设计带来了三个关键优势：

认证加密（AEAD） ：GCM 在加密数据的同时生成一个认证标签（Authentication Tag），任何对密文的篡改都会导致标签验证失败。这意味着解密操作天然具备完整性校验能力，无需像 AES-CBC 那样额外搭配独立的 MAC 函数。

高性能与并行化：CTR 模式的加密过程可以高度并行化。在支持 AES-NI 指令集的现代 CPU 上，GCM 的吞吐量显著高于需要串行加密的 CBC 模式。

无需填充：作为流加密模式，GCM 不需要对明文进行填充（Padding），可直接处理任意长度的数据。

AES-256-GCM 的具体参数为：256 位（32 字节）密钥、96 位（12 字节）Nonce、128 位（16 字节）认证标签。这些参数由 NIST SP 800-38D 和 RFC 5116 共同规范。

二、在 Signal Protocol 栈中的位置

整个加密系统的架构遵循 Signal Protocol 的分层设计，AES-256-GCM 位于协议栈的对称加密层：

ed25519.ts        → 身份密钥（Ed25519 签名/验签）
    ↓
x25519.ts         → DH 密钥交换（X25519）
    ↓
x3dh.ts           → 密钥协商握手（4 次 DH + HKDF → root_key）
    ↓
hkdf.ts           → HKDF-SHA256 密钥派生 + AES-256-GCM 加解密
    ↓
ratchet.ts        → Double Ratchet 状态机（DH 棘轮 + 对称棘轮）
    ↓
session.ts        → 会话编排（绑定以上所有模块）

AES-256-GCM 的加密/解密实现位于 hkdf.ts 文件中（即 aesEncrypt / aesDecrypt 函数），而密钥生成、Nonce 计算和二进制封包格式则由 envelope.ts 负责。这种分层使得每一层关注单一职责：X3DH 负责初始密钥协商，Double Ratchet 负责密钥持续更新，AES-256-GCM 专注于消息内容的实际加解密。

三、密钥派生与消息加密流程

在 ratchet.ts 中，每条消息的加密遵循严格的棘轮步进流程：

DH 棘轮（提供前向安全） ：定期使用 X25519 生成新的 DH 密钥对，通过 DH 输出更新 root_key。具体实现中，ratchetStep 函数以 rootKey 作为 salt、dhOutput 作为 IKM，通过 HKDF-SHA256 派生出新的 rootKey（info = [0x01]）和新的 chainKey（info = [0x02]）。

对称棘轮（从 chain key 派生消息密钥） ：每次发送消息时，从当前的 chainKey 派生出一次性使用的 messageKey。代码中采用 SHA-256 直接派生（messageKeyStep 函数），messageKey = SHA-256(chainKey)。派生完成后，旧的 chainKey 被丢弃——这是对称棘轮“只进不退”特性的核心体现。

AES-256-GCM 加密：用派生出的 32 字节 messageKey 配合 12 字节 Nonce 加密明文。Nonce 必须对每条消息唯一——在同一个密钥下重复使用 Nonce 会彻底破坏 GCM 的机密性和完整性保证，攻击者可恢复明文或伪造密文。

Key Erasure：加密完成后立即用 fill(0) 覆盖内存中的 messageKey，确保密钥材料不在内存中残留。

四、Nonce 管理：不可妥协的安全红线

AES-GCM 最关键的约束是：对于同一个密钥，Nonce 绝不能重复使用。这是因为 GCM 内部使用 CTR 模式，如果 (key, IV) 对重复，加密同一密钥下不同明文将导致严重的机密性灾难。

在 Signal Protocol 的 Double Ratchet 框架中，这一问题通过两个机制解决：

  1. 每条消息使用独立的消息密钥：对称棘轮为每条消息派生全新的 messageKey，每个 messageKey 只加密一条消息。

  2. Nonce 随消息密钥唯一确定：envelope.ts 中负责 Nonce 的计算和编解码，确保每个 (messageKey, nonce) 组合的全局唯一性。

根据 NIST SP 800-38D 的指导，使用随机生成 IV 的实现应将单密钥加密次数限制在 2³² 次以内以降低 Nonce 碰撞概率。Signal 的棘轮机制天然符合这一要求——密钥在每次 DH 棘轮后更新，实际单密钥加密次数远低于此上限。

五、安全属性：前向安全与后妥协安全

AES-256-GCM 与 Double Ratchet 的结合提供了两个关键安全属性：

前向安全（Forward Secrecy） ：即使某一时刻的消息密钥被泄露，由于对称棘轮的单向派生特性（chainKey → messageKey 不可逆），攻击者无法回溯推导出之前的消息密钥。DH 棘轮每次更新 root_key 时丢弃旧密钥，进一步强化了这一特性。

后妥协安全（Post-Compromise Security / Break-in Recovery） ：每次 DH 棘轮执行时，双方交换新的 DH 公钥并派生新的 root_key 和 chainKey。即使攻击者曾经获取了某个时间点的密钥材料，一次完整的 DH 棘轮交换后，安全属性会被重置——新派生的密钥与旧密钥在数学上无关。

六、工程实现要点

在基于 Web Crypto API 的实现中，AES-256-GCM 的密钥通常以 CryptoKey 对象管理，默认设置 extractable = false 以防止密钥材料被脚本读取。加密操作通过 crypto.subtle.encrypt 和 crypto.subtle.decrypt 完成，认证标签由 Web Crypto API 自动附加和验证。

总结

AES-256-GCM 在 Signal Protocol 中扮演着“最后一道防线”的角色。它凭借 AEAD 的认证加密特性，在保证消息机密性的同时提供了内置的完整性保护；配合 Double Ratchet 的密钥更新机制，实现了前向安全与后妥协安全；严格的 Nonce 唯一性要求则通过每条消息独立密钥的设计得到满足。正是这一层层递进的安全设计，使得 Signal Protocol 能够为数十亿条消息提供端到端的加密保护。
